# tifl mobile shell (Capacitor / iOS)

A thin [Capacitor](https://capacitorjs.com/) wrapper around the SolidJS web
client in `../web`. The compiled web bundle is the app; this directory only adds
the native container, the API base URL for a server-less origin, and (later)
native modules for offline audio/story storage and haptics.

- `capacitor.config.json` — appId, `webDir: ../web/dist`, plugin config.
- `ios/` — generated by `npx cap add ios` (run once, on macOS). Committed.
- `node_modules/`, `ios/App/Pods/`, build output — gitignored.

## How the pieces fit

```
web/build.mjs --mobile   ->  web/dist/  (index.html gets window.__API_BASE_URL__)
cap sync ios             ->  ios/App/App/public/  (copy of web/dist)
xcodebuild / Xcode       ->  tifl.app / .ipa
```

`web/src/api.ts` reads `window.__API_BASE_URL__` first, so the shell talks to a
remote server while the browser build (no injected global) stays same-origin.

Default API base: `https://atlas.tail7e8149.ts.net:8443/api/v1` (atlas, exposed
over Tailscale with `tailscale serve` for TLS). Override at build time:

```
TIFL_MOBILE_API_BASE=https://host:port/api/v1 make mobile-web
```

## Setup (macOS)

Prerequisites: Xcode, CocoaPods, and a JS runtime — `npm`, or `bun` (dolos has
no standalone `node`; use `bun install` and `bun ./build.mjs --mobile` there).

`ios/` is committed, so a fresh clone only needs:

```
cd mobile && npm install          # or: bun install
make -C .. mobile-sync            # build web (--mobile) + cap sync ios
npm run open:ios                  # then build/run from Xcode
```

`npx cap add ios` was already run on dolos; re-run it only to regenerate the
native project from scratch.

Verified on dolos (Xcode 26.3): Debug simulator build with
`CODE_SIGNING_ALLOWED=NO` succeeds.

## Iterating

From the repo root:

```
make mobile-sync          # rebuild web, copy into ios/, refresh pods
```

then Cmd-R in Xcode. Only re-run `npm install` when dependencies change.

## Auth across origins

The WebView origin is `capacitor://localhost`; the API is a different origin.

- **CapacitorHttp** is enabled in `capacitor.config.json` — `fetch()` goes through
  native networking, so there is no CORS preflight and the native cookie jar
  holds the refresh cookie.
- The server must send the refresh cookie as **`SameSite=None; Secure`** (it is
  `Path=/api/v1/auth`, `HttpOnly` already) so it rides cross-site requests.
  `Secure` is satisfied by the `tailscale serve` HTTPS front. Confirm the atlas
  deployment sets `secureCookie` / `cookieSecure = true`.
